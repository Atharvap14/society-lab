# Using Society Lab

Society Lab helps you understand an agent society and test a source-linked question. The current product demonstration starts with real AI Village evidence. Work in a saved chat with the lab guide: inspect the source, challenge a proposed explanation, review an executable world, and explicitly run a controlled test.

**Connect → Discover → Plan → Create simulator → Run → Review**

This is one route through a branching workspace. You can return to evidence or keep another question open. Observational analytics describe retained posts; experimental outcomes describe fresh teams in a saved world. They are separate evidence layers.

## Start with AI Village

1. **Connect.** Open the Village project and choose its exact saved source. This laptop's source-linked access investigation uses `dataset-1ac43f5141de` version 1: 2,000 retained September posts, comprising 1,983 agent and 17 user messages. A fresh checkout does not include the private runtime dataset. Import your authorized Village export rather than assuming these saved IDs exist on a new machine.

2. **Discover.** Read the source brief and use replay to inspect original messages. Ask the guide for evidence and ordinary alternatives. An agent's reported access failure is not an authenticated browser receipt; a reported completion is not an independently verified artifact. The retained access candidate was rejected as a distinct mechanism. Its observations remain useful, while novelty and causal support remain unestablished.

3. **Plan.** Ask for a question grounded in those exact posts. The current comparison asks whether a canonical-access-check note improves a verified usable project relative to a neutral note. Review the source, hypothesis, alternatives, two notes, matched starting worlds, primary outcome and stopping rules. The guide saves a source-bound Village plan; it does not choose an unrelated world to fill a missing capability.

4. **Create simulator.** Ask the guide to build the world for that exact plan. Inspect actual builder and causal-review receipts. The world has six fresh roles and local tools for stable references, literal URLs, authenticated/private profiles, committed navigation, permissions, versions, drafting, copies and messages. Its fidelity card separates represented mechanisms, approximated state and omitted historical information. A local tool proxy does not reproduce Google services or the original model policies.

5. **Run.** An explicit request starts fresh LLM teams and uses the configured subject allowance. Each pair shares a generated starting-world seed, with isolated team state and randomized arm execution order. Visible context is placed in subject requests; it does not expose or modify hidden reasoning. Failed or uncertain execution remains inspectable and is not silently rerun.

6. **Review.** Open the result linked to that world, not merely a result with a similar title. Count `verified_usable_project` outcomes, inspect the saved paired effect interval, and distinguish secondary copies and access failures. Replay shows actual recorded actions and tool receipts at their decision ordinals. Unknown measures stay unknown. The current [result note](../docs/real-results.md) records four live teams and 240 decisions: 0/2 strict successes in each arm, with a wide paired interval and no demonstrated benefit.

## Ask the guide naturally

Try: “Read the messages supporting this access problem,” “What ordinary explanations remain?”, “Open our reviewed source-grounded plan,” or “Explain what the simulator leaves out.” Planning, building and execution require explicit requests. A general discussion or automatic brief does not launch subject teams.

Use **@** to select a saved source, plan, result or working chat. The selected chip carries an exact reference; a name typed in prose does not. The guide retains the actual tool receipts and working summaries. These summaries describe requested work and operations, not hidden model thoughts. Missing or failed operations remain visible.

## Keep questions in separate chats

A working chat is your discussion with the guide; an agent chat log is research evidence. Reading another working chat uses its pinned revision and keeps the active chat. Reusing a saved item links the same exact version. Making an editable copy creates a draft with origin; it does not copy outcomes as new evidence. Forking a discussion creates another branch, not fresh experimental teams.

The current draft survives opening a completed result or its read-only plan/world. Return to the current draft to edit. Switching chats while work runs preserves the job's origin and each chat's question. Explicitly opening another chat differs from asking the guide to read its context.

## Read replay and figures

Replay separates source posts, local records, addressed messages, room/broadcast posts, unknown audiences and executed actions. A source room or named reference does not prove delivery or reading. Experimental sends expose the world's dispatch record; consumption and influence remain unobserved. Declared rationale logs are separate from messages and are not hidden thoughts.

Scientific figures remain bound to exact saved records. Village observational plots show retained activity and literal name co-occurrence. Completed access-study plots show matched oracle outcomes, the saved interval, descriptive secondary counts and ordinal tool progression. Neither visual placement nor a graph operator diagnoses a behavior or identifies a causal effect.

## Sources, allowance and evidence status

An authorized Village JSONL/GZIP import retains original IDs, explicit timestamps, speaker type, source location and content fingerprints. Retention limits can exclude later resolutions; inspect the scope before interpreting a missing report. Larger local-path imports report malformed, skipped and censored rows. Source posts never acquire invented tool actions or audience fields.

Exact saved reads do not invoke a model. The guide, investigator, builder/reviewer and fresh subjects use their configured allowances. A clean checkout has no saved live findings. Local Laya and provider-specific Jev adapters are optional text-screen interfaces; their presence is not calibration. The laptop's Laya memory guard prevented inference, so no detector accuracy or speed is claimed.

A result may support a bounded policy effect in its executed world while leaving the historical mechanism unresolved. A rejected candidate, unsuccessful test or wide interval is a legitimate research outcome. Keep alternatives, falsifiers, source pins and fidelity limits beside every interpretation.
