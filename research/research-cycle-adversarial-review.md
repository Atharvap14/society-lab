# Independent research-cycle challenge

This review exercises local checkpoint authority, typed evidence, recovery, source retrieval and shared accounting. Its fixtures use temporary registries and small executed CPU worlds. No hosted provider, production registry, mounted-source scan or historical experimental artifact is changed. The reviewer is a separate agent in the same development task; this is not institutional independence, an external certification or a causal replication.

## Reproduced defects and corrections

**A rehashed terminal checkpoint could manufacture completion.** Starting from a failed registration fixture, changing only the appended checkpoint's status/phase to completed made the old resume path return it without result, proof, claims or theory. The corrected path requires the entire completed stage graph, exact typed stage/artifact references, authoritative completed child jobs, and the exact root-job terminal closure bound to the returned cycle version/hash and plan. A blocked return likewise must retain its exact authoritative closure. The finite hypothesis packet is reconstructed canonically; inflated status, mechanism support, replication or scope cannot authorize new curation. A failed/running checkpoint cannot use the already completed root job to mint a fresh closure.

**A late concurrent writer could erase a recovered completion.** In an actual temporary complementary-world run, the first worker paused immediately after saving its subject result. A second worker resumed from that retained identity, replayed and checked it, and completed the cycle. The first worker then overwrote the latest checkpoint with its older failure state. Only one subject experiment ran, but the visible completion was lost. The correction uses `Store.compare_and_put`: an exact expected previous version/hash, an append-only inserted version returned directly, and at most two typed job publications in one SQLite transaction. A stale worker records the artifact references it knows in a conflict trace and returns a validated latest checkpoint instead of posting shared failed statuses. A failure update preserves an already completed child. Completed/failed root closure and the corresponding checkpoint now publish atomically.

**Quota preflight demanded a second allocation for saved work.** A fake local provider consumed exactly the registered 48 ledger reservations while executing real CPU complementary-world subjects, then interrupted after the completed result was persisted. Resume demanded space for 48 additional calls before attempting recovery and blocked at the original ceiling. The new-work preflight now runs only after authoritative recovery returns no artifact. Recovery, replay, finite checking and guarded hypothesis curation finish with the same 48 reservations and no second subject execution. The fake provider test establishes orchestration and accounting behavior only; it is not an LLM trial.

**A failed-stage floating attempt count could launch a new retry.** The original completed-stage guard checked integer attempts, but an appended failed audit checkpoint with `attempts=1.0` entered resume and attempted a new child identity ending in `audit.2.0`. The corrected ingress validates every stage's strict integer count, child identity, allowed state fields, typed artifact reference and sequential progress before any retry. A failed checkpoint must additionally agree with its exact authoritative root-job closure. These checks reject an altered pending/running/failed declaration instead of allowing a new worker to turn it into authoritative completion.

**A completed resume left its invocation job running.** A genuine failed-audit CPU cycle resumed successfully, but its separate `.resume.1` claim stayed active indefinitely. The correction publishes the invocation's actual returned cycle identity/status, or retains requested/latest identities when an exception prevents a return. This update addresses observability of the local invocation; it does not change the authoritative cycle or subject-job completion. A killed process can still leave an unresolved claim and is not automatically declared complete.

**A replacement root ID could reset child identities.** Appending the original all-pending snapshot after a saved subject execution, with only its root job ID changed, passed the frozen-plan check and launched another CPU subject experiment under fresh child-job names. Checkpoint validation now binds root job ID, deterministic cycle ID and plan to the original immutable version. This applies at resume ingress and when returning a competing writer's checkpoint, so a rehashed old snapshot cannot bypass existing child claims by changing their prefix.

## Challenge coverage

The independent tests check the completed and blocked return paths, rehashed failed-to-completed and running/failed all-completed forgeries, exact child/root job closure, numerical type substitution in pinned versions, hypothesis promotion, compare-and-put immutability/conflicts, completed child preservation, and a concurrent stale writer. Eight competing ledger callers can reserve only three available slots; reservations remain counted even when not finished. Additional tests run the real `ResearchAgents` citation gate: an existing dataset ID that was not supplied or retrieved is rejected, while a successful `read_evidence` call refreshes the nested provider schema and permits the exact retrieved ID. A positive authoring fixture then compiles, registers, executes, replays, checks facts and curates a bounded hypothesis. All provider callbacks in these checks are explicitly CPU fakes.

Existing cycle tests cover four executable world dispatches, capability/fit/design rejection, exact blueprint selection, original source drift, backend drift, intentional artifact-library append, incomplete/uncertain execution, exhausted safe-stage attempts, source manifest/report mutation, forged replay proof and finite numeric claims. CLI/API tests exercise actual temporary loopback jobs and the distinct inner cycle identity. The public hooks call the same allowlisted cycle API; they do not supply arbitrary function names or runner callbacks from JSON.

## What the checks establish

For code and registry state within this local trust boundary, a saved cycle cannot advance by trusting a free completed flag, a stale proof reference, a reported all-supported claim flag or a promoted theory packet. The executed world's exact registration, archive, report, independent replay and finite facts must agree before new curation. A recovered result is reused under its original job identity; uncertain claimed subject execution is blocked rather than relaunched. Shared atomic call reservations enforce the supplied absolute cap. Concurrent checkpoint publication cannot silently lose a completed branch or overwrite the exact inserted reference with a racing latest read.

The causal and semantic boundary remains unchanged: scripted policies test infrastructure. Finite outcome claims concern only the registered synthetic task and backend. The generated library theory remains an untested analogue hypothesis; source fit, history, mechanism, mediation, novelty and generalization are not established by orchestration.

## Remaining limits

A completed resume returns the recorded historical cycle unchanged, after its retained authority/bindings are checked. It deliberately does not claim a fresh execution-archive read or current raw-source attestation. A test mutates the local report after completion and confirms that repeated resume returns the same historical reference without adding a fresh-pass assertion. A new independent audit is needed for current bytes.

The cycle call ceiling is an absolute shared-ledger count, not a lease on remaining slots. New calls elsewhere can consume capacity; the conservative guard also blocks a free pending CPU stage if shared usage later exceeds this cycle's original ceiling. This policy limit can be stricter than actual additional monetary cost. It is documented rather than treated as authorization to raise the ceiling. A provider retry or transport failure still consumes its reserved call, and semantic completion is not guaranteed within an authorized budget.

The SQLite compare-and-put transaction is a local coordination guarantee. It is not a distributed lease, provider idempotency contract, protection against an operator rewriting the database/jobs, or automatic reconciliation after a process is killed mid-provider action. A retained uncertain stage stays blocked; a terminal checkpoint without authoritative root closure is not repaired by asserting success.

Exact source pins and supplied/retrieved IDs authenticate imported record membership and which evidence the role received. They do not prove that a source entails a statement, that a reviewer judged fit correctly, or that a provider internally consumed the request. Separate role execution is not independent institutional/model validation. Supplied fit reviews remain explicitly unverified judgments. The live builder's observed-fact requirement improves citation discipline but does not make its prose a verified historical claim.

The declarative CLI rejects duplicate JSON keys and nonfinite values. The HTTP host's general JSON parsing currently uses the standard last-key-wins parser before the typed cycle API; callers should submit canonical unique-key JSON. This is a boundary consistency limitation, not an authorization bypass demonstrated here: boolean mode/cap/reference types are still validated by the cycle and the loopback action queue requires its host token. A future host-parser tightening belongs in the server contract, outside this review's source ownership.

No model effect, historical mechanism or wider freedom from confounding follows from this review.
