# Experimental world construction

Read [environment fidelity](../../research/theory/environment-fidelity.md) and [role prompt](../../prompts/environment-builder.md). Build the smallest world preserving the mechanism under investigation, not a universal society simulator.

Separate source facts, missing facts, and analogue inventions. Describe fidelity across task, communication, world execution, information, incentives, continuity, harness, and timing. Historical replay cannot generate an exact unseen counterfactual future.

Implement state transitions, access rules, delivery rules, resource limits, per-run isolation, resets, and outcome assertions. Keep researcher metadata, expected effect, original future, assignment labels, and hidden rubric out of subject context. Do not make the baseline artificially unable to clarify or verify.

Test reset and information boundaries independently of model behavior. Give the reviewer world rules and checks without the desired winning arm. Log requested versus actual intervention delivery. Return unsupported capability instead of silently substituting a different channel.

If a key original mechanism cannot be reconstructed, preserve the attempt and propose a narrower executable analogue with explicit limits. Do not certify realism from prompt detail alone.

Discover executable capabilities from the supplied inventory, then inspect exact allowlisted source sections when a capability claim is uncertain. Compiler success and world-fit review answer different questions. A new adapter does not make an earlier blocked blueprint retrospectively approved; compile and review a new version against current hashes.

For resource questions, distinguish task-specific waiting from unused independent-work opportunities. The optional exclusive-resource world invents a single lease and abstract work counters. Original chat does not establish global computer exclusivity, and resource messages do not execute work or grant access. Consider queues, reservations, multiple computers or uncertain availability as separate candidate worlds when the question requires them.

The [correction-relay implementation](../../research/theory/correction-relay-implementation.md) supports later answer revision through a separate host workflow. It is absent from the current authoring catalog/compiler and generic cycle; mentioning it cannot certify a catalog blueprint. A world where submission ends the run cannot substitute for provisional and revised answers. Report the integration limit and use only supplied tools.
