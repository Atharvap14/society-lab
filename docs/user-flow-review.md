# Product journey review

An actual LLM evaluator preregistered eight expected user actions and subjective success probabilities before the browser journey. The frozen registration is in [user-flow-preregistration.json](user-flow-preregistration.json); observations and saved-state checks are in [user-flow-observations.json](user-flow-observations.json).

The route read an exact editable copy through @, saved a fresh plan, built a world with real builder/reviewer agents, ran real subject teams, changed project while the run continued, returned to its results, replayed an older experiment, reused an exact old plan, forked the discussion, and reloaded the branch. The independent unsent idea in the other project survived. Eleven saved-state checks verified unchanged original hashes, the new result, branch references and actual tool receipts.

This was not a clean first-pass success. The record retains a refused wrong source reference, a build request that initially only navigated, a run request incorrectly requiring its own future output, a reuse claim without a receipt, an artifact-ID search gap, and an immediate reload that returned the origin before the branch was confirmed settled. Corrections and retries are distinguished from the original observations. The guide's first requested prose summary opened the findings page but did not fully restate the counts; the page displayed the saved counts and uncertainty correctly.

The repairs include source-bound plan validation, broader but bounded imperative parsing, correct ready-world input instructions, exact saved-world routing, artifact-ID search, preserved project expansion, editor focus/value protection, and a bounded receipt correction for single explicit workspace mutations. No completed or uncertain mutation is automatically rerun. Missing receipts cannot support success prose.

Independent authored tests exercise 180 actual SQLite workspace transitions and 192 browser-controller transitions, including stale responses, overlapping saves, independent drafts, historical replay and long-range return to saved work. Those fixtures establish software behavior. They are separate from this observed real-agent route and from scientific subject outcomes.

The demo is one possible path. A user may begin with a question, a saved experiment, a source or a different chat, branch midway, and return to an earlier result. Saved source, plan, world and result identities remain explicit across those paths.
